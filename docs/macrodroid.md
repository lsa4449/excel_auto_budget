# MacroDroid 설정 (갤럭시 S25 / One UI 7 기준)

휴대폰에 온 카드 결제 알림을 서버(`/webhook`)로 그대로 넘겨주는 역할만 합니다.
해석(금액·가맹점·카테고리)은 전부 서버가 하므로 MacroDroid 쪽은 단순하게 유지합니다.

> 메뉴 이름은 One UI·MacroDroid 버전에 따라 조금 다를 수 있습니다.

---

## 0. 준비물

| 항목 | 값 (예시) |
|---|---|
| 서버 주소 | `http://100.101.102.103:8000` (Tailscale IP) 또는 `http://192.168.0.10:8000` (집 Wi-Fi) |
| 토큰 | `.env`의 `API_TOKEN` 값 |

먼저 휴대폰 브라우저에서 `서버주소/health` 를 열어 `{"ok":true,...}` 가 보이는지 확인하세요.
안 보이면 MacroDroid 설정보다 네트워크(README의 "3. 휴대폰에서 서버 접속") 문제부터 해결해야 합니다.

---

## 1. 갤럭시 권한·배터리 설정 (가장 중요)

갤럭시는 백그라운드 앱을 공격적으로 재우기 때문에 이 설정이 없으면 며칠 뒤 조용히 멈춥니다.

1. **알림 접근 권한**
   설정 → 애플리케이션 → 우측 상단 ⋮ → 특별한 접근 → **기기 및 앱 알림** → MacroDroid **허용**
2. **SMS 권한**
   설정 → 애플리케이션 → MacroDroid → 권한 → **SMS 허용**
3. **배터리 제한 해제**
   설정 → 애플리케이션 → MacroDroid → 배터리 → **제한 없음**
4. **절전 예외**
   설정 → 배터리 → 백그라운드 사용 제한 → *잠자는 앱 / 깊은 잠자는 앱* 목록에 MacroDroid가 **없어야** 함
   → **절대 잠자지 않는 앱**에 MacroDroid 추가
5. **최근 앱에서 잠금**
   최근 앱 화면 → MacroDroid 아이콘 탭 → **이 앱 잠그기** (메모리 정리 시 종료 방지)
6. 카드사 앱과 **삼성 메시지** 앱의 알림이 켜져 있는지 확인

## 2. 매크로 ① 카드 문자(SMS/LMS/MMS)

카드 결제 문자는 길어서 대부분 **LMS(장문, MMS로 분류)** 로 옵니다.
MacroDroid의 "SMS 수신" 트리거는 MMS/LMS를 놓치는 경우가 있어서,
**삼성 메시지 앱의 알림을 잡는 방식**을 기본으로 권장합니다.

### 트리거
`+` → 기기 이벤트 → **알림** → **알림 수신(Notification Received)**
- 애플리케이션 선택: **메시지 (com.samsung.android.messaging)**
- 텍스트 일치: **포함(Contains)** → `승인`
  - 취소 건도 받으려면 같은 트리거를 하나 더 추가하고 `취소` 입력 (트리거는 OR로 동작)
- "진행 중 알림 무시" 체크

### 액션
`+` → 웹 상호작용(Web Interactions) → **HTTP 요청(HTTP Request)**
- 요청 방식: **POST**
- URL: `http://서버주소:8000/webhook`
- **쿼리 파라미터(Query Parameters)** 탭에 추가
  | 이름 | 값 |
  |---|---|
  | `token` | 내 API_TOKEN |
  | `source` | `sms` |
  | `title` | `[not_title]` |
  | `text` | `[notification]` |
- 값 입력란 옆 `...` 버튼 → **매직 텍스트**에서 `[not_title]`, `[notification]` 을 선택하면 오타가 없습니다.
- "URL 인코딩" 옵션이 있으면 켜 두세요. (줄바꿈·특수문자 때문에 JSON 본문보다 쿼리 파라미터가 안전)

> **대안 (SMS 트리거)**: 알림 미리보기가 잘려서 들어온다면 트리거를 `전화/SMS → SMS 수신` 으로 바꾸고
> 내용 `포함: 승인`, 액션의 `text` 값을 `[sms_message]`, `sender` 값을 `[sms_number]` 로 바꿉니다.
> 두 매크로를 동시에 켜 둬도 서버가 같은 결제를 **중복 저장하지 않습니다.**

### 제약 조건 (선택)
- 없음. 필요하면 "Wi-Fi 연결됨" 등을 걸 수 있지만, 밖에서도 쓰려면 비워 두세요.

## 3. 매크로 ② 카드사 앱 푸시

### 트리거
**알림 수신**
- 애플리케이션 선택: 사용하는 카드사 앱 (예: 신한 SOL페이, 삼성카드, KB Pay, 현대카드, 롯데카드, 우리WON카드, 하나Pay ...)
- 텍스트 일치: **포함** → `원`  (승인 문구가 제목에만 있는 카드사가 있어 금액 단위로 거르는 게 안전)

### 액션
매크로 ①과 같고 값만 다릅니다.

| 이름 | 값 |
|---|---|
| `token` | 내 API_TOKEN |
| `source` | `push` |
| `title` | `[not_title]` |
| `text` | `[notification]` |
| `sender` | `[not_app_name]` |

`sender`(앱 이름)를 같이 보내면 본문에 카드사 이름이 없는 푸시도 카드사를 구분할 수 있습니다.

> 카카오톡 **알림톡**으로 결제 알림을 받는 카드라면 매크로 ②의 앱 목록에 카카오톡을 추가하고
> 텍스트 일치를 `승인` 으로 두세요. 서버가 결제 형식이 아닌 메시지는 자동으로 무시합니다.

## 4. 동작 확인

1. 매크로 편집 화면 우측 상단 ⋮ → **매크로 테스트(액션 실행)** → 서버 로그에 요청이 찍히는지 확인
2. 실제로 소액 결제를 해 본 뒤 `서버주소/docs` → `GET /transactions` 로 저장 확인
3. 인식이 안 된 알림은 `GET /unparsed` 에 원문이 남습니다. 그 원문을 `tests/test_parser.py`에 추가하고 파서를 보완하면 됩니다.
4. MacroDroid → 메뉴 → **시스템 로그** 에서 HTTP 응답 코드 확인
   - `401` 토큰 불일치 / `연결 실패` 서버 꺼짐·주소 오류

## 5. 자주 생기는 문제

| 증상 | 원인 / 해결 |
|---|---|
| 며칠 지나면 안 들어옴 | 1번 배터리·절전 예외 설정 다시 확인, 기기 재부팅 후 MacroDroid 실행 여부 |
| 같은 결제가 두 번 저장됨 | 카드사·금액·시간이 다르게 파싱된 경우. `.env`의 `DEDUP_MINUTES` 늘리기 |
| 가맹점이 이상하게 잘림 | `/unparsed` 또는 엑셀 상세내역에서 원문 확인 후 파서 보완 |
| 집 밖에서만 실패 | 서버가 집 Wi-Fi 주소로만 열려 있음 → Tailscale 사용 |
